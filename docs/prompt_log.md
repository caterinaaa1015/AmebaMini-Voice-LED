# AI 協作紀錄

## 紀錄 1：建立無開發板的可測試版本

- **需求提示詞**：建立 Python 專案，將「左邊開燈」控制藍燈、「右邊開燈」控制綠燈；尚未有 Ameba 時仍可測試，非控制語句不可改變 LED。
- **AI 產生內容**：`command.py`、`serial_controller.py`、`main.py` 與單元測試。
- **設計決定**：採白名單解析；模擬模式標示為「非實體 LED 驗證」；實體模式必須收到 `STATUS` 回覆才顯示 LED 狀態。
- **測試結果**：已安裝 Python 3.12，執行 `py -3.12 -m unittest -v`，5 個測試全部通過。

## 紀錄 2：預定的異常測試

- **測試情境**：輸入「今天天氣很好」。
- **預期結果**：解析為 `UNKNOWN`，不呼叫序列埠控制器，LED 狀態不變。
- **測試情境**：使用 `--simulate-disconnect` 後輸入「左邊開燈」。
- **預期結果**：顯示通訊失敗，且顯示 LED 實際狀態未知。

## 紀錄 3：Windows 套件安裝失敗修正

- **問題**：執行 `py -3.12 -m pip install -r requirements.txt` 時出現 `UnicodeDecodeError: 'cp950' codec can't decode ...`。
- **原因判斷**：Windows 的 pip 以 CP950 讀取 requirements 檔案，但檔案中的中文註解是 UTF-8。
- **修正提示詞**：請保留套件名稱，但將 requirements.txt 的註解改成 ASCII，避免 Windows 終端機編碼造成 pip 解碼失敗。
- **修正結果**：已將註解改為英文；重新安裝成功，並確認 `pyserial`、`SpeechRecognition`、`PyAudio` 可正常匯入。

## 紀錄 4：加分功能

- **需求提示詞**：加入左右 LED 閃爍三次與中英文指令，但非控制語句不得改變 LED。
- **AI 產生內容**：新增 `BLUE_BLINK_3`／`GREEN_BLINK_3` 白名單命令，並在 Ameba 韌體加入 `LED,<color>,BLINK,3`。
- **設計決定**：閃爍三次後目標燈固定關閉，Ameba 再回傳最終 `STATUS`；英文語音辨識用 `--language en-US` 明確選擇，避免將中英文辨識混為不可靠的猜測。

## 紀錄 5：語音辨識數字格式修正

- **測試現象**：說「左邊閃爍三次」時，辨識文字是「左邊閃爍3次」，被白名單判定為 `UNKNOWN`。
- **原因**：初版只列出中文數字「三次」，沒有包含語音服務常輸出的阿拉伯數字 `3次`。
- **修正結果**：加入 `左邊閃爍3次`、`右邊閃爍3次` 與「三下」變體，仍維持白名單保護。

## 紀錄 6：肉眼相同但 Unicode 不同的辨識字

- **測試現象**：除錯輸出顯示語音文字為 `左邊閃爍3次`，但 Unicode 是 `U+5DE6 U+908A U+9583 U+720D U+0033 U+6B21`。
- **原因**：白名單的「爍」是 `U+723D`，語音服務卻回傳 `U+720D`；兩者畫面相似但字元不同。
- **修正結果**：在 `normalise()` 將觀察到的 `U+720D` 統一為 `U+723D`，再進行白名單比對。
